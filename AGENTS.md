# Repository instructions

This repository contains an unofficial, safety-focused Node.js/TypeScript CLI for synchronizing media that a user is authorized to access from MyFans to a PikPak rclone target.

## Build and validate

- Require Node.js 22.12 or newer.
- Install exactly with `npm ci`.
- Run the full gate with `npm run check`.
- Use `npm test` for deterministic tests and `npm run build` for `dist`.
- Inspect the publish set with `npm pack --dry-run` during release work.

## Safety invariants

- Never run live `sync`, cleanup execution, or `rollback` while developing or testing.
- Never put tokens, cookies, personal plan IDs, personal remote paths, private manifests, or downloaded media into source, fixtures, logs, plans, or examples.
- Keep planning read-only. Require persisted plans and exact digest confirmation for external mutations.
- Revalidate remote state immediately before writes and prohibit overwrites.
- Keep cleanup separately planned and confirmed. Delete only verified files contained by the configured work directory.
- Rollback reverses renames only; it never deletes uploaded media.
- Use per-post reconciliation. Do not require source, local, and remote counts to match.

## Code boundaries

- Keep deterministic policy in `src/core`, external integrations in `src/adapters`, orchestration in `src/services`, persistence in `src/state`, CLI infrastructure in `src/cli`, and one public command implementation per file in `src/commands`.
- Keep `src/cli.ts` as a side-effect-only executable entry point. Build and inspect the Commander tree through `createProgram()` instead of importing the executable in tests.
- Use dependency injection through `src/ports.ts` so tests never need live services.
- Keep `--json` stdout to one documented envelope. Send diagnostics to stderr and preserve stable error codes.
- Update runtime validation, `schemas`, tests, README, and changelog together when a public contract changes.
- Preserve unrelated and ignored private migration artifacts in the working tree.

## Agent skills

- Use `$myfans-to-pikpak-operator` for import planning, operation, status, verification, cleanup, and rollback requests.
- Use `$myfans-to-pikpak-maintainer` for code, review, test, dependency, schema, and release work.
- `.agents/skills` is canonical. `.claude/skills` is generated by `npm run agents:sync`; do not edit generated copies.
